04 · Agent systems · Open source

AEGIS

A mission system for coding agents that tries to solve one ugly problem: autonomous work is useless when the agent can sound finished without being able to prove what actually happened.

Mission loop
Mission → state → execute → evidence → verify → ship.
Persistent stateCapability probesUsage routingRelease gatesRegression memory
Python stdlib coreDeterministic benchmark harness

Thesis

Evidence or it didn’t happen.

AEGIS treats claims like “tests passed,” “deployed,” or “worker available” as things that need executable proof, not nice prose. Mission state survives across sessions and completion is derived from evidence.

The engine

MISSIONgoal

The surrounding system

The repository combines the mission engine with usage-aware routing, shared context tooling, an end-to-end ownership skill and benchmark missions designed to expose whether the workflow improves real agent performance.

Capability probes

A worker has to prove it can perform before it appears as an available route.

Git-aware staleness

Evidence can become stale when the code it verified changes, so “passed once” is not permanent truth.

Checkpoint + resume

Mission files keep decisions and evidence recoverable instead of depending on one giant context window.

Components

aegis-engine+aegis-ceo-skills+usage-optimizer+second-brain-context+benchmarks

Most of the core helpers deliberately target Python 3.9+ standard library only. The interesting complexity is in the rules and evidence model, not a tower of dependencies.
